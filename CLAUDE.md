# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A GTK 4 / Libadwaita desktop remote for Android TV / Google TV, written in pure Python (PyGObject). It talks to the TV over the **Android TV Remote protocol v2** (ports 6466/6467, TLS + hand-encoded protobuf), not ADB. App ID `io.github.tecix.TvRemote`; it started as a fork of erenseymen/android-tv-remote, so the Python package is still named `gnome_adb_tv_remote` and the config dir is still `~/.config/android-tv-remote/`, even though ADB and scrcpy are gone. CONTRIBUTING.md's "Code Organization" still mentions ADB/scrcpy and is out of date.

## Commands

There is no test suite, linter config or CI.

```bash
# Build + install the Flatpak and launch it (needs flatpak-builder and org.gnome.Sdk//49)
./build-and-run.sh

# Same steps by hand
flatpak-builder --user --install --force-clean build-dir flatpak/io.github.tecix.TvRemote.yml
flatpak run io.github.tecix.TvRemote

# Shell inside the sandbox (logs, debugging)
flatpak run --command=sh io.github.tecix.TvRemote

# Validate AppStream metadata
appstreamcli validate data/io.github.tecix.TvRemote.metainfo.xml
```

Running from source without Flatpak: `rsa` and `psutil` must be importable next to the system PyGObject (e.g. a venv created with `--system-site-packages`). `MainWindow` calls `Gio.Settings.new("io.github.tecix.TvRemote")`, which aborts if the schema isn't installed, so compile it somewhere outside the repo and point GSettings at it:

```bash
glib-compile-schemas --targetdir=/tmp/tvremote-schemas data/
GSETTINGS_SCHEMA_DIR=/tmp/tvremote-schemas PYTHONPATH=src python3 -m gnome_adb_tv_remote
```

`flatpak/python3-dependencies.yaml` is generated by `flatpak-pip-generator`. Regenerate it whenever you change the dependencies in `pyproject.toml`. Don't edit it by hand.

## Architecture

**Threading model.** Network I/O never runs on the GTK main thread. `AndroidTvRemote` (`core/remote_v2.py`) owns one TLS socket plus a daemon reader thread. Sends are serialized with a lock, and TV-pushed events (volume, power, current app, disconnect) arrive through callbacks registered with `set_handlers()`. Those callbacks fire on the reader thread, so `MainWindow` wraps every one of them in `GLib.idle_add`. Connecting, scanning and pairing also run in worker threads that report back with `GLib.idle_add`. Keep this pattern: never touch widgets from a callback that comes from `core/`.

**Two input backends with one interface.** `MainWindow` (`ui/main_window.py`, the app coordinator) holds an `AndroidTvRemote` (direct route) and, optionally, a `HomeAssistantRemote` (`core/home_assistant.py`). Both expose the same send methods (`send_keycode`, `send_long_press`, `send_text`, `reset_text`, `expand_notification_panel`, `connected`, `device_info`). `MainWindow._input()` picks the backend according to the `home-assistant-mode` setting. If you add a new kind of command, add it to both classes. The HA backend turns each key into `remote.send_command` with an `input keyevent <code>` shell command, using `AKEYCODE_MAP` from `remote_v2`. It runs requests on a single worker thread and drops queued D-pad repeats once more than 4 are pending. Even in HA mode the direct connection stays open, so volume keeps syncing from the TV.

**Protocol without heavy dependencies.** `remote_v2.py` hand-encodes and parses the few protobuf messages it needs (`_varint`, `_msg`, `_parse`). `keystore.py` builds a self-signed X.509 client certificate with a hand-written DER encoder and the `rsa` package. This avoids depending on `protobuf` or `cryptography`, so the Flatpak stays pure Python and architecture-agnostic. Keep it that way. Pairing (`PairingSession`, port 6467) hashes the code the TV shows together with both RSA public keys. After pairing, the TV trusts the certificate stored under `~/.config/android-tv-remote/remote/`.

**Second TV.** Besides the main device (for example a streaming box), the window can hold another `AndroidTvRemote` (`_tv_remote`, IP from the `tv-ip` setting). `TvRemoteDialog` uses it to switch HDMI inputs. Auto-reconnect and discovery (`SubnetScanner` on `REMOTE_PORT`, matching devices by saved model name) handle both devices when their IPs change.

**Other pieces.** `MprisService` exports the remote over D-Bus as `org.mpris.MediaPlayer2.AndroidTVRemote`, which must match the `--own-name` in the Flatpak manifest. `RemotePanel` builds the buttons and handles hold-to-repeat and long press. Keyboard shortcuts are stored as a JSON dict in the `keyboard-shortcuts` GSettings key and merged over `DEFAULT_SHORTCUTS` in `preferences_dialog.py`.

## Settings and secrets

- All persistent UI and device state lives in GSettings (`data/io.github.tecix.TvRemote.gschema.xml`).
- `setup.py` `data_files` lists every installed data file and icon by name. A new icon or data file is not installed until you add it there.
- The Home Assistant token is **not** stored in GSettings. It lives in `~/.config/android-tv-remote/home-assistant/token`, created with mode 0600 by `save_token()`.
- Material icons are loaded from `/app/share/io.github.tecix.TvRemote/icons/material` inside the Flatpak and from `data/icons/material` when running from source (`ui/ui_utils.py`).

## Conventions (from CONTRIBUTING.md)

PEP 8, type hints on all function parameters and return values, a docstring on each module, and `from __future__ import annotations` at the top of every module.
